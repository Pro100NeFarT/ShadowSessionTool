# Засіб тіньових сеансів (ShadowSessionTool)

Невеликий адміністративний застосунок для Windows Server (RDP/RDS) — перегляд активних сеансів, тіньове підключення без згоди користувача, керування сеансами та розсилка повідомлень. Заміна ручного набору команд `query session` / `mstsc /shadow`.

![.NET Framework 4](https://img.shields.io/badge/.NET%20Framework-4.0-blue) ![Windows](https://img.shields.io/badge/Windows-Server%202012%20R2%2B-0078D6)

## Можливості

- **Список сеансів** — користувач, ID, стан, ім'я сеансу; отримується через нативний WTS API (не через парсинг тексту консолі), тому коректно працює незалежно від мови ОС (українська/російська/англійська)
- **Пошук** за іменем користувача в реальному часі
- **Сортування** по кліку на будь-який заголовок колонки
- **Тіньове підключення** (`Підключитися`) — перегляд і керування чужим сеансом без запиту згоди користувача (`mstsc /shadow ... /noConsentPrompt`)
- **Перейняти сеанс (за паролем)** — аналог команди «Подключить» у Диспетчері завдань Windows: повністю замінює ваш поточний сеанс сеансом іншого користувача (через `tscon.exe`), а не просто переглядає його
- **Перевірка та увімкнення групової політики** тіньового підключення без згоди користувача (`Set rules for remote control...`) — зелений/червоний індикатор і кнопка одним кліком
- **Завершення сеансів** — одного, кількох вибраних (Ctrl/Shift), або всіх відключених одразу
- **Надсилання повідомлень** вибраним сеансам або всім одразу (крім власного), із шаблонами (закриття 1С/BAS, дозвіл на роботу, попередження про перезавантаження)
- **Планове перезавантаження сервера** — через N хвилин або на конкретну годину, з автоматичною розсилкою попередження всім активним сеансам і можливістю скасувати
- **Контекстне меню (ПКМ)** — усі дії з тією ж логікою доступності, що й кнопки, з коректною поведінкою виділення (як у Провіднику)
- **Три теми оформлення** — світла, темна, синя; вибір запам'ятовується між запусками
- **Автооновлення** — застосунок сам перевіряє новішу версію в цьому репозиторії при кожному запуску й пропонує оновитися

## Вимоги

- Windows Server 2012 R2 або новіший (перевірено також на Windows Server 2022) чи Windows 10/11
- Права адміністратора (застосунок запитує підвищення прав автоматично при запуску)
- Інтернет-доступ — лише для автооновлення; без нього застосунок працює повністю функціонально, просто не перевіряє нових версій

## Встановлення

1. Завантажте `ShadowSessionTool.exe` з [Releases](../../releases) або напряму з кореня репозиторію
2. Запустіть — Windows запитає підтвердження підвищення прав (UAC)

Встановлення не потрібне: один файл, без залежностей окрім .NET Framework 4 (вже вбудований у Windows Server 2012 R2+ та Windows 10+).

## Збірка з вихідного коду

Проєкт — один файл `ShadowSessionTool.cs`, компілюється вбудованим у Windows компілятором `csc.exe` (з .NET Framework), без потреби встановлювати .NET SDK чи Visual Studio:

```powershell
$csc = "$env:WINDIR\Microsoft.NET\Framework64\v4.0.30319\csc.exe"
& $csc /target:winexe /platform:anycpu `
    /out:ShadowSessionTool.exe `
    /win32manifest:app.manifest `
    /win32icon:ShadowSessionTool.ico `
    /reference:System.dll,System.Windows.Forms.dll,System.Drawing.dll `
    ShadowSessionTool.cs
```

Іконку (`ShadowSessionTool.ico`) можна перегенерувати скриптом `GenerateIcon.ps1`.

## Автооновлення — як це працює

При кожному запуску застосунок звіряє власну версію з файлом [`version.txt`](version.txt) у цьому репозиторії (`raw.githubusercontent.com`, HTTPS, без токена). Якщо версія новіша — пропонує оновитися; після згоди завантажує новий `.exe`, закриває всі запущені копії процесу та підміняє файл.

Щоб випустити нову версію: підняти номер у `version.txt` і закомітити оновлений `ShadowSessionTool.exe` в гілку `main`.

## Примітки щодо безпеки

- Тіньове підключення без згоди користувача — це навмисна адміністративна функція (стандартна можливість RDS), яка вимагає відповідної групової політики; використовуйте лише на серверах, якими адмініструєте
- «Перейняти сеанс» передає пароль користувача `tscon.exe` як параметр командного рядка — це документований спосіб Microsoft, але пароль теоретично на мить видимий іншим процесам з достатніми правами на тому ж сервері (обмеження самого `tscon`, не застосунку)
- Застосунок не збирає й не передає жодних даних, окрім перевірки версії при оновленні
